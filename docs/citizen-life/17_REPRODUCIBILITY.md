# Reproducibility

Reproducibility here does not mean “the same Citizen id returns.” It means: **Birth can happen again**, and evidence can show that a *new* life occurred with the same structural rites.

## What occurred

The laboratory cycle:

```
Destroy Citizen (export first)
  → Install (Birth)
  → Boot
  → Sync (when a package waits)
  → Export Birth Package
  → lab-report
```

Script observed: `citizen-seed/lab_reproduce.sh`.

After Destroy→Birth, new `citizen_id` values appeared. Prior Birth Packages remained on disk with their own hashes.

## Why “new id” is success

If Destroy + Install returned the *same* genome, Birth would be a lie — a reload, not a birth. New Identity proves irreversibility of the previous life and reality of the new one.

## What must match structurally

- Timeline epochs through Alive (and Sync when an update package exists)  
- Evidence event families of Birth  
- Outside-LLM verdict when all planes are present and the Runtime scan is clean  

## What must differ

- `citizen_id`  
- Birth timestamps  
- Archive hashes of Birth Packages  

## What evidence exists

- Distinct packages in `lab/exports/`.  
- Lab reports with `ALL_MEASURED_LIFE_OUTSIDE_LLM` on complete lives.  
- Disarm refusal if install is attempted on an already-born home without Destroy.

Reproducibility is a property of the **rite**, not of a single immortal id.
